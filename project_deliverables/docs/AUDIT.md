# Test Suite Audit

| # | Category | Raw Flawed Code | Identified Flaw | Corrective Fix |
|---|---|---|---|---|
| 1 | **Tautological Boundary Check** | `BigDecimal rate = pricingService.calculateMonthlyRate(tier, 60, "SAVE20");`<br>`assertTrue(rate.compareTo(BigDecimal.ZERO) >= 0);` | Testing `rate >= 0` against outputs of $17.50 (BASIC), $92.50 (PRO), and $355.00 (ENTERPRISE) creates false confidence. It never exercises the $0.00 floor clamp because all valid promotion outputs are strictly positive. | Replace the illusory check with an exact boundary assertion on the domain's minimum possible rate ($17.50):<br>`BigDecimal minRate = pricingService.calculateMonthlyRate(SubscriptionTier.BASIC, 37, "SAVE20");`<br>`assertThat(minRate).isEqualByComparingTo("17.50");`<br>`assertThat(minRate.scale()).isEqualTo(2);` |
| 2 | **Weak & Scale-Coupled Assertions** | `assertNotNull(rate);`<br>`assertEquals(new BigDecimal(expectedBaseRate), rate);` | `assertNotNull` is a redundant, weak assertion. `assertEquals` uses `BigDecimal.equals()`, which strictly compares scale in addition to value (e.g., `50.0` vs `50.00` fails), leading to brittle financial tests. | Use AssertJ `isEqualByComparingTo` for monetary value equivalence, paired with explicit scale verification:<br>`assertThat(rate).isEqualByComparingTo(expectedBaseRate);`<br>`assertThat(rate.scale()).isEqualTo(2);` |
| 3 | **Incomplete Exception Verification** | `assertThrows(InvalidVoucherException.class, () -> pricingService.calculateMonthlyRate(tier, age, invalidVoucher));` | Merely verifying the exception type ignores whether the exception contains meaningful diagnostic context or message details. | Capture the exception instance and assert that the error message is non-null, non-blank, and informative:<br>`InvalidVoucherException ex = assertThrows(InvalidVoucherException.class, () -> pricingService.calculateMonthlyRate(tier, age, invalidVoucher));`<br>`assertThat(ex.getMessage()).isNotNull().isNotBlank();` |
